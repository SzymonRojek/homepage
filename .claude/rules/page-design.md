# The page

What the page is made of and why, part by part, with what was tried and dropped. Each fact lives in one place; if a part changes, this is the file to change with it. The parts are in page order, and the sections carry small numbered headings ("01 / How I use AI" and so on, from `sections.ts`).

A single page aimed at recruiters for test automation and QA roles (developer roles possibly too, through the `#case-study-talent-outreach-developer` link). The theme of the page is a tester who also builds software (the duotone portrait, the projects' code and test colours, and the footer's question), told with as little repetition as possible: each fact lives in one place. The design is a "colour block": the page opens and closes on near-black with a green undertone (`brand.dark`, `#0B1513`: the hero and the footer), the deep brand green (`brand.background`) is the one strong colour inside it (the raised top bar, the featured project card, and the How I test band in the dark theme), with cream text and a sunny yellow accent, around a warm sand page (`#F4EAD6`) with white bands and cards that alternate down the page (redesigned on 2026-10-16 after a reference page the user picked). Testing is green (`theme.colors.qa`), code is terracotta (`theme.colors.dev`). Headings use Bricolage Grotesque, body text Geist, tiny labels and the section numbers Geist Mono (the reference page's fonts). Parts in order (sections: How I use AI, How I test, Projects, Experience, Skills, References, each with a small numbered heading, "01 / How I use AI" and so on):

## The parts, in page order

- **Skip link and floating top bar:** a rounded pill, sticky 12px under the top of the window (8px on phones), on the content column, in three states (`useBarState`, `nextBarState` tested on its own). At the top of the page it shows nothing of itself over the hero, only its contents: no fill, no edge, no shadow. Scrolling down hides it from the very first step, over the hero too (it slides up out of sight in 0.3 s, at once with reduced motion), keeping the look it had, so it goes bare and never flashes green (`filled`). Scrolling back up 16px from where the page last turned brings it back raised (`revealAfter`); going down hides it from the first step, always. Within 120px of the top (`clearNear`) it gives up its fill on the way up and on a jump, so the fade back to bare is over before the page stops: at `y = 0` alone the green vanished as the scroll ended, which read as a jolt. Going down, `clearNear` changes nothing. Raised, on every screen size: `colors.topBar` at 94% (the deep green in the light theme, a step lighter `#1C4D46` in the dark one, where How I test is the deep green; 1.27:1 against it), the page blurred under it (`backdrop-filter`) and two shadows (`brand.pillShadow`), so it reads as a layer. It has no edge in either theme: `colors.topBarEdge` draws the menu panel's edge alone, and the panel keeps the bar's colour and shadow. It fills smoothly (0.25 s) while it is still over the dark hero (`fadesOverHero`, `$smooth`), and at once past it: a jump lands over the light sections, where a fading bar left its cream links unreadable for a moment, which axe caught in CI (an e2e test reads the colour straight after a jump, another checks the fade over the hero). A jump of more than 60% of the window in one step keeps it in sight, and so does a click on a link to a section: the links scroll smoothly, in small steps that would read as scrolling down, so the bar holds raised while that scroll keeps moving (a 400 ms quiet timer, no fixed limit, and not `scrollend`, which Chrome fires right after the click; an e2e test clicks three links in turn under load). A few pixels of tremble are ignored, keyboard focus inside brings it back (`:focus-within`), and an open menu keeps it raised. After a reload below the top it stays hidden until the visitor scrolls up, never flashing (issue #25): a script in `index.html` marks `<html data-restoring-scroll>`, keeps the page unseen until it has jumped back before the first paint, and `useInitialScroll` drops the mark once the fonts are in and it has jumped again; while the mark is there the bar is hidden (CSS before React, `useBarState` after). On the contact pill the arrow is decorative, so the link is named "Contact"; it nudges 4px forward on hover and keyboard focus, still with reduced motion, and it goes to `#contact` and scrolls to the contact card: it is a way to the contact, not the contact itself. Below desktops (up to `tabletHorizontalMax`) the button sits on the content's right edge (only the note is kept to 36em, so the button can reach it; an e2e test measures it); on desktops it starts under the note. No photo (the hero shows it), no speech bubble (tried and dropped), and the full name appears only in the © line.   The theme follows the OS setting, including live changes while the page is open, until the visitor uses the light/dark switch. After that, the choice is saved in `localStorage("dark")` and the OS setting is ignored, until the visitor switches back to the OS theme: that drops the saved choice and the page follows the OS again (two states, as Lea Verou and NN/g advise, instead of a separate "System" option).

## Colour, bands, rhythm and type

- Colour roles: the brand band (`theme.colors.brand`: deep green, cream text, yellow accent) is used for the top bar, the hero and the contact card only. On the cream page, `primary` (deep green in light, yellow in dark) is for buttons and links; green (`qa`) is testing, terracotta (`dev`) is code; the Automation card edge is half and half because it is both. No glows or gradient text. The window's scrollbar is the page's too: the theme's `primary` as a slim 6px thumb (`borderRadiusSmall`) inside a 10px lane left transparent, so the page's own colour shows through it and no stripe runs beside the dark bands (`GlobalStyle`). The `::-webkit-scrollbar` rules apply only where a pointer can grab the thumb (`hover: hover` and `pointer: fine`), since a width turns the system's overlay bar into a classic one that never leaves, which is right on a desktop and clutter on a touch screen; engines with no pseudo-element (Firefox, and Safari from 26.2) take `scrollbar-color` instead, behind `@supports not selector(::-webkit-scrollbar)`, because Chromium drops the pseudo-elements as soon as `scrollbar-color` is set. The classic bar takes 10px off the content width, so the e2e `layout` spec measures the gutters from `documentElement.clientWidth` and never from the viewport.
- Section backgrounds alternate so each section reads as a block, and the page opens and closes on the same near-black (`brand.dark`: the hero and the footer): How I use AI sits right under the hero (`aiBand`: the page's sand in the light theme, `deepShade` in the dark one), then How I test (`storyBand`: white in the light theme, the deep brand green in the dark one), then the page colour (Projects) and bands one step up (`BandSection`, `$band`: `card` for Experience, `quote` for References) take turns with sections on the page colour (Skills), down to the footer: light: dark, sand (How I use AI), white, sand, white, sand, white, dark; dark theme: dark, `#0E2A26` (How I use AI), green, page `#0B1513`, band `#1F302B`, page, band, dark. With six sections, strict alternation inside the light half is impossible if How I test and References both stay white, so How I use AI leads the page on a strong colour instead: both themes then lighten away from the hero and settle into the gentle alternation (light 1.94, 9.55, then 1.19 four times; dark 1.22, 1.25, 1.53, then 1.34). A band under the sticky top bar must never take the theme's `topBar` colour. Bands that follow one another meet edge to edge (`.section-band + &` drops the margin). Neighbouring backgrounds differ by about 1.15:1 or more, enough to see each section as a block without stripes (white next to the old cream was 1.09:1 and ran together). Keep the alternation when a section moves: a white card on a white band needs its border, and a card of the page's tone vanishes on the page (the Skills Learning card became white with a border). Pastel bands per section were tried and dropped (they read as a template and blur what green and terracotta mean), and so was a soft test-green band for How I test.
- Section headings (`SectionLabel`) are small monospace labels with the section's number in front ("02 / How I test"), as on the reference page, and have no decorative bar above them (a short yellow bar was removed because it read as AI-made). The number comes from `sectionNumber` (`sections.ts`, the page's order) through `data-number` and CSS, so screen readers and the page's text get the name alone; keep `sectionOrder` in step with the page.
- **Buttons:** main actions fill with `primary` and darken on hover (`primaryHover`, about 1.3:1, text still AA); the yellow ones on the green band darken to amber (`brand.accentHover`). Secondary actions (Demo, Code, the × that closes the technical details) share `secondaryButton` from `ButtonLink`: the card colour with a thin border, and on hover the page's tone fills them (`secondaryHover`) and the border darkens. A new button reuses one of these.
- **Decorations stay inside the page's width:** the yellow rings (hero top-right, footer bottom-left) and the bug in How I test (top-right) hang off a corner of the content column, not of the window: their side offset adds `columnInset` (`core/App/contentColumn.ts`), so from 1256px up they stop moving with the window and keep the same place next to the content (asked by the user; their sides show in full on wide screens). Up to 1256px nothing changes. A new decoration on a full-width band does the same. The e2e `layout` spec measures all three at 1280, 1600, 1920 and 2560px.
- **Vertical rhythm:** one value for the space above and below a section's content, `theme.layout.section` (40px, 24px on phones): a band's padding, the gap before a section on the page colour, and the footer's top. Use it for any new section instead of a number of its own. A section's heading (`SectionLabel`, its first line) adds `sectionOpening` above itself on top of it (32px padding, 24px up to `tabletVerticalMax`, 16px on phones; padding, since a margin would collapse into a page-colour section's margin), so every section opens the same distance down (72 / 64 / 40px), with 16px below the label to the section's big line or content.
- **Page width and gutters:** one content column for everything, from `theme.layout`: at most 1160px of content, centred, with side gutters of 48px on desktop, 32px up to `tabletHorizontalMax` and 16px on phones. Use the `contentColumn` css helper (`core/App/contentColumn.ts`) for anything that must line up with the page edge (the page `Container`, the top bar row and its menu panel, the hero content). Full-width bands (top bar, hero) keep their background edge to edge and put `contentColumn` on an inner element; never add their own side padding. The hero photo ends on the right edge of the column, on phones too, under left-aligned text.
- **Fonts:** self-hosted variable woff2 files in `public/fonts/` (Bricolage Grotesque 200–800, Geist 100–900 and Geist Mono 100–900, one file per alphabet for every weight, latin and latin-ext, from @fontsource-variable 5.3.0, OFL; the reference page's fonts). The `@font-face` rules live in `index.html` and the two first-screen files (Bricolage Grotesque and Geist, latin) are preloaded there, so the page paints once in its real fonts: no text reflow and no jumping photo on load. Preload `href`s start with `/fonts/` (Vite adds the base); `url()`s in the inline style use `%BASE_URL%`. Don't import fonts from JavaScript again. On a slow connection the page is drawn before the fonts arrive, so each has a fallback face there (`Geist Fallback`, `Bricolage Fallback`, after the real font in the stacks: Arial, Liberation Sans or Roboto, scaled with `size-adjust` and ascent/descent overrides, only for the letters the real fonts have) that breaks lines in the same places, so the swap moves nothing (layout shift 0.056 in PageSpeed before the fallbacks; `e2e/fonts.spec.ts` delays the files and checks it). Measure the values again if a font or much of the text changes.
- **Icons** in `public/`: `favicon.svg` (the green "SR" initials in a yellow circle, as in the top bar), `favicon.png` (32px fallback), `apple-touch-icon.png` (180px) and `icon-192.png` / `icon-512.png` for `manifest.json` (`icon-192.png` is also a `rel="icon"`, since Google Search doesn't use SVG favicons), all generated from the same design; keep them in step with the logo.
- **Headings:** h1 is the hero headline, led by the visually hidden name and title, h2 is a page section (`SectionLabel`, the small numbered label; the big lines under it, such as "Beyond the obvious bugs", are h3 or a paragraph), h3 is a card or group, h4 is a project tile. Sections use `aria-labelledby` pointing to their heading `id`.
